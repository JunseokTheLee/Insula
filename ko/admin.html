방문 통계

사이트를 연 브라우저 수를 브라우저마다 하루(한국 시간) 한 번 집계합니다. 그 순간 로그인 세션이 있으면 회원, 아니면 게스트입니다. 같은 사람이 두 기기로 오면 2, 게스트로 왔다가 같은 날 로그인하면 양쪽에 1씩, JavaScript 를 실행하지 않는 방문과 알려진 크롤러는 세지 않습니다. supabase_visit_stats.sql 의 record_visit() 이 기록하며 아래 "방문자 수 집계" 옵션으로 끌 수 있습니다. 신규 작품·신규 회원은 기존 테이블에서 셉니다.

아직 사용할 수 없습니다 — Supabase SQL 에디터에서 supabase_visit_stats.sql 을 실행하세요.

캠페인

캠페인 목록에서 새로 만들기

수정은 캠페인의 제목·설명을 바꿉니다. 크기와 기준 이미지는 캠페인 페이지의 Reshape 로 바꿉니다. 격자 이미지 생성은 격자 이미지 캐시가 생기기 전에 만든 캠페인에만 보입니다. 칸 색을 작은 PNG 로 한 번 만들어 두면 그 캠페인 페이지가 더 이상 모든 칸을 DB 에서 읽지 않습니다. 캠페인을 삭제해도 작품은 지워지지 않고 작가의 풀로 돌아갑니다. 보관본(이전 버전)은 원본 캠페인과 함께 삭제됩니다.

캠페인이 없습니다.

풀 대기 작품 0

아직 어느 캠페인에도 들어가지 못한 작품입니다(새로 올라온 작품, 캠페인 삭제로 돌아온 작품). 매칭은 업로드·캠페인 생성·reshape·작품 제거·캠페인 삭제 때만 돌기 때문에 지금 배치로 바로 돌릴 수 있습니다. 진행 중인 캠페인의 빈 칸과 색이 맞지 않는 작품은 여기 그대로 남습니다.

대기 중인 조각: —개 — 조각은 자기 캠페인에 색이 맞는 빈 칸이 생길 때 자동으로 들어갑니다.

풀에 대기 중인 작품이 없습니다.

작품 조각

작품은 올릴 때 브라우저가 "사이트 옵션" 의 분할 개수대로 조각을 만들고, 모자이크에는 색이 맞는 조각만 들어갑니다. 조각이 없는 작품(이 기능 전에 올라온 작품, 조각 생성에 실패한 작품)은 "조각 생성" 으로 만듭니다 — 통째로 배치돼 있던 작품은 칸에서 풀려 조각으로 다시 배치됩니다. 분할 개수를 바꾼 뒤에는 "전체 다시 생성" 으로 모든 작품을 새 개수로 다시 자릅니다.

아직 사용할 수 없습니다 — Supabase SQL 에디터에서 supabase_mosaic_pieces.sql 을 먼저 실행하세요.

작품 썸네일

작품을 올릴 때 브라우저가 썸네일(긴 변 480px, 원본이 그보다 작으면 원본 그대로)과 초소형 썸네일(16×16, 캠페인 격자용)을 만듭니다. 둘 중 하나라도 없는 작품 수를 보여주며, 썸네일 생성은 그 작품들의 원본을 읽어 빠진 것을 한 건씩 다시 만듭니다. 작품 자체는 바뀌지 않습니다.

아직 사용할 수 없습니다 — Supabase SQL 에디터에서 supabase_mosaic_micro_thumbs.sql 을 먼저 실행하세요.
